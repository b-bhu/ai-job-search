# Lesson 04 — The verification loop

Prepared lesson. Status: Not started. Track: Core.

## Objective

Explain the cycle from a change to observed evidence.

## Predict

A test expects exactly the string generated by the implementation. What bug might that test miss?

Ask this first in conversation and wait. The following explanation is prepared material, not learner evidence.

## Analogy

A chef tastes the dish, compares it with the intended flavor and adjusts it. Reading the recipe aloud is not tasting.

## Model

Change, run, observe, compare and correct. Anchor the comparison in a user requirement or independent fixture. Tests that repeat the implementation can repeat its mistake.

1. **Change**: Candidate fix
2. **Run**: Real path
3. **Observe**: Evidence
4. **Compare**: Requirement
5. **Correct**: Next attempt

## Worked example

Reproduce the false success banner with a failed-RPC fixture before the fix. Run the same fixture after the fix. Keep the before/after evidence and also check the success path.

```ts
const result = runTransfer({ rpcResult: 'failed' });
expect(result.banner).toBe('Failed');
expect(result.inputAmount).toBe('0.01');
```

Illustrative teaching snippet. Referenced helper functions and branded types may be placeholders. This is not an installed program or a complete production implementation.
