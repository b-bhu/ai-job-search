# Agent-engineering tutoring procedure

Read README.md, progress.md, the latest session-log.md entry and open review-queue.md rows before teaching. Read the current lesson note. Source references and deeper caveats live in sources.md.

This is a separate course in the same AI Job Search project. Do not edit learning/ progress or existing Solana course material. The format adapts .claude/commands/learn.md: understanding, one manageable concept, actual evidence, no time estimates and no fabricated passes. Career profiles remain canonical elsewhere and must not change based on participation.

## Teaching agreement

1. Start with where we stopped and one concrete prediction or question. Wait for the answer before choosing the explanation depth.
2. Use the lesson's analogy and visual model. Define new terms. Use a familiar frontend action, then connect to TypeScript or Solana only as useful.
3. Give one worked example, then one fresh attempt. Give progressive hints. If you supply the solution, record it as assistance and use a new variation for assessment.
4. Never ask all lesson questions together or dump the entire roadmap into one reply. The visual course reveals four phases, but conversation follows the learner's answer.
5. Code is optional reading support at first. The learner's current independent proficiency is unassessed. Avoid assuming that existing product work means a foundational concept is mastered.
6. For conceptual checks, an explanation, trace, prediction or diagram can be evidence. For implementation claims, require actual execution and observable output. Reading, tutor-written code and a browser read mark do not demonstrate independent competence.
7. Use statuses: Not started, Learning, Practising, Demonstrated, Retained, Needs review. Scope every claim to what was observed. Retention requires a later variation.
8. At a meaningful stopping point, update progress.md with the exact next question, append the actual attempt and assistance to session-log.md, and update review-queue.md only for observed gaps. Keep history. An unanswered question remains pending.
9. Browser notes are learner-supplied evidence only after they share them. The browser cannot edit these Markdown records automatically. Do not imply automatic study monitoring.
10. Exercises use fake/local fixtures. No wallet actions, signing, real submission, production edits or installations. Verify current official tooling documentation only when a separately requested executable exercise needs it.
