# Course references

Sources checked on 2026-09-28. These support our lessons; they are not a list of courses you must complete. Read the relevant section when we use it, then apply the idea in our own exercise. Verify version-specific commands again when the practical module begins.

| Modules | Reference | How we will use it |
|---|---|---|
| M01, M03 | [Harvard CS50x](https://cs50.harvard.edu/x/?nt=1) | Selected explanations of computation, memory, algorithms, and data structures; our exercises remain aligned with this course |
| M01, M04, M10 | [MIT Missing Semester](https://missing.csail.mit.edu/) | Shell, development tools, debugging, Git, and packaging practice as those needs arise |
| M02 | [MDN JavaScript Guide](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide) | Reference for language behavior, with small examples we can predict and modify |
| M02 | [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/) | Types, interfaces, narrowing, and expressing constraints clearly |
| M02, M05 | [MDN: Using promises](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Using_promises) | Trace completion, errors, and promise chains before hiding them behind abstractions |
| M05, M06 | [MDN: Overview of HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview) | Requests, responses, and the client/server conversation |
| M05, M09 | [Node.js: The event loop](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick) | Explain runtime behavior after we have observed small programs; internal phase names need not be memorized |
| M07 | [PostgreSQL Tutorial](https://www.postgresql.org/docs/current/tutorial.html) | SQL and relational concepts, followed by reference chapters when deeper questions arise |
| M07, M09 | [PostgreSQL: Transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html) | Connect multi-step operations to commit and rollback experiments |
| M08 | [OWASP: Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) | Turn access rules into explicit checks and negative tests |
| M12, M13 | [The Rust Programming Language](https://doc.rust-lang.org/book/) | Main Rust reference, selected by current concept rather than assigned all at once |
| M12, M13 | [Rustlings](https://rustlings.rust-lang.org/) | Small compiler-guided exercises alongside the Rust explanations |
| M15 | [Solana core concepts](https://solana.com/docs/core) | Account and program model, instructions, transactions, PDAs, CPIs, and fees |
| M15, M18 | [Solana SDKs](https://solana.com/docs/clients) | Choose a supported client for the exercise and verify compatibility with the selected toolchain |
| M16, M17 | [Anchor documentation](https://www.anchor-lang.com/docs) | Program structure, testing tools, IDL, account lifecycle, tokens, and deployment references |
| M16, M17 | [Anchor account constraints](https://www.anchor-lang.com/docs/references/account-constraints) | Check exactly what a constraint enforces; pair every important assumption with a test |

The module sequence, projects, and assessment method are a custom teaching plan. They are not claims that any one linked course covers our complete syllabus. Add focused sources for deeper topics when their lessons are prepared, especially where the ecosystem changes quickly.
